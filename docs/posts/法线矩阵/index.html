为什么法线不能直接用模型矩阵变换？

结论#

法线要用 $M^{-\mathsf T}$ 变换，而不是 $M$。记住这一句就够了。

① 只有存在非均匀缩放或切变时，这件事才有意义。 如果变换只由平移、旋转、均匀缩放组成，直接用 $M$ 就是对的。

② “逆转置"只是特例，更一般的答案是伴随矩阵的转置。 逆转置要求矩阵可逆，而伴随矩阵总是存在、不需要做除法。 另有一个符号陷阱要留意：$\det M < 0$（镜像 / 负缩放）时，伴随给出的方向与逆转置相反—— 用伴随就必须补一个 $\operatorname{sign}(\det M)$，否则只有镜像物体上的法线是反的。

③ 工业界的取向是"尽量不在 shader 里算”。 Unity 和 UE 靠 CPU 端预计算；Godot 给每个实例打标记，只有非均匀缩放时才在顶点着色器里算一次。 真正的效率排序是：不算 > 用 CPU 预计算 > 换乘法顺序 > 在 shader 里算。

一、问题：法线为什么不能用同一个矩阵变换#

你的顶点着色器里大概率有这么一行：

mat3 normalMatrix = transpose(inverse(mat3(model)));

它是对的。但为什么位置、切线、纹理坐标都用同一个 model，法线却要单独算一个矩阵？

一个矩阵可以一致地变换点、线、三角形，甚至切向量——因为这些量都跟着几何走。

法线不行。原因在于法线的定义方式和其他量根本不同：

法线不是"空间里指向某个方向的箭头"，而是"垂直于切平面的那个量"。写出来就是

$$\mathbf{n} \cdot \mathbf{t} = 0$$

对所有切于该点的向量 $\mathbf{t}$ 成立。即：

模型经过了一串变换，这些变换可以合并成一个矩阵 $M$。切线随之变成 $\mathbf{t}' = M\mathbf{t}$。 请找出一个矩阵 $N$，使变换后的法线 $\mathbf{n}' = N\mathbf{n}$ 仍然满足 $\mathbf{n}' \cdot \mathbf{t}' = 0$。

满足的解就是 $N = M^{-\mathsf T}$。

二、推导：从"保持垂直"到 $M^{-\mathsf T}$#

跟随约束#

“垂直"就是点乘为零。写成矩阵乘法就是：

$$\mathbf{n}'^{\mathsf T}\mathbf{t}' = 0$$

记号约定：本文统一按列向量处理（与 RTR4 一致），所以 $\mathbf{n}^{\mathsf T}$ 是行向量， 行向量乘列向量得到一个标量——这正是点乘。这里特意用 $\mathsf T$ 写成矩阵形式，是为了下一步能直接代入矩阵。 （注意约定差异：HLSL / UE 里是行向量，代码写成 mul(v, M)；GLSL 是列向量，写成 M * v。 数学内容完全一样，只是乘法顺序反过来。）

代入 $\mathbf{n}' = N\mathbf{n}$、$\mathbf{t}' = M\mathbf{t}$，并注意 $(N\mathbf{n})^{\mathsf T} = \mathbf{n}^{\mathsf T}N^{\mathsf T}$：

$$\mathbf{n}^{\mathsf T} N^{\mathsf T} M\, \mathbf{t} = 0$$

我们希望它对所有满足 $\mathbf{n}^{\mathsf T}\mathbf{t} = 0$ 的向量对都成立。取 $N^{\mathsf T}M = I$ 显然能满足，于是

$$N = (M^{-1})^{\mathsf T} = M^{-\mathsf T}$$

这就是"逆转置”。2000 组随机矩阵（含拉伸与切变）里，直接用 $M$ 变换法线的垂直性违反率是 100%， 而 $M^{-\mathsf T}$ 是 0%——因为随机矩阵几乎不会恰好落在"旋转 + 均匀缩放"那个特殊子集里。

模型经过一串变换时不必逐级求逆：合并成 $M$ 后求一次即可，因为 $(M_1M_2)^{-\mathsf T} = M_2^{-\mathsf T}M_1^{-\mathsf T}$。

但这个解是唯一的吗#

上面只证明了充分性。要谈必然性，令 $A = N^{\mathsf T}M$。 固定 $\mathbf{t}$：要求 $\mathbf{n}^{\mathsf T}(A\mathbf{t}) = 0$ 对所有 $\mathbf{n} \perp \mathbf{t}$ 成立， 这意味着 $A\mathbf{t}$ 平行于 $\mathbf{t}$。

而这个性质必须对每个 $\mathbf{t}$ 都成立。一个把每个向量都映成自身倍数的矩阵，只能是标量矩阵：

$$A = \lambda I \quad\Longrightarrow\quad N = \lambda\,M^{-\mathsf T}$$

结论：法线变换矩阵唯一到一个标量因子。

这一步不是数学洁癖，它直接解释了两件事：

  1. 为什么变换后必须重新归一化——那个 $\lambda$ 让长度不可信，而方向才是法线的全部
  2. 为什么可以用伴随矩阵顶替逆矩阵——两者差的正是这样一个标量因子（见下文"更准确的答案"）

三、更准确的答案：伴随矩阵#

“逆转置"有一个前提——$M$ 必须可逆。而

$$M^{-1} = \frac{\operatorname{adj}(M)}{\det M}$$

当 $\det M = 0$（矩阵奇异）时，逆不存在。但伴随矩阵总是存在。用伴随的转置来变换：

$$\operatorname{adj}(M)^{\mathsf T} = (\det M)\,M^{-\mathsf T}$$

按第二节的结论，它与 $M^{-\mathsf T}$ 只差一个标量因子。但要注意这个因子是带符号的：

$\det(M)$ $\operatorname{adj}(M)^{\mathsf T}$ 给出的方向
$> 0$（保向变换） 与 $M^{-\mathsf T}$ 相同 ✓
$< 0$（镜像 / 负缩放） 与 $M^{-\mathsf T}$ 相反

第二行不是缺陷，而是 $\det$ 带符号的直接后果。 （“负缩放要翻转法线"这类说法就是从这类符号问题里来的——但那句话说得含糊， 它可能指三件不同的事，后面会把它们分开。）

当 $\det M > 0$ 时：伴随的转置 + 归一化 = 正确答案，而且不需要求逆。

实测：3000 组随机矩阵里，$\det>0$ 的 1539 组方向全部一致，$\det<0$ 的 1461 组方向全部相反——没有一个例外。

那什么时候真会碰到不可逆的变换？很少：

  • 投影矩阵不是。它在齐次坐标下可逆——四种常见配置（三种透视 + 正交）的行列式都非零， 2000 组视图空间点正投影再反投影的最大误差是 4.6e-13。 “投影不可逆"这个说法指的是透视除法那一步：NDC 只剩 3 个分量，4 个未知数 3 个方程，解不回 4 维。 但管线里有额外信息——$z_{\text{ndc}}$ 编码了深度，由它反推 $w$ 就能重建。 这正是引擎里"从 NDC 反投影回视图空间"的做法：不在投影空间里硬算光照，而是先反投影回视图空间。
  • 真正不可逆的是退化变换：某个轴的缩放因子为 0（物体被压成一个平面）、或者动画形变塌陷。

所以伴随矩阵的价值主要不在"救奇异矩阵”，而在下面这件事：

它不需要做除法。 要用 $M^{-\mathsf T}$，你得先算余子式、再除以 $\det M$； 而 $\operatorname{adj}(M)^{\mathsf T} = C$ 直接就能用。GPU 上除法比乘法贵， 而且 $\det M$ 很小时"除以一个小数"还会放大误差——不用除的写法两头都占便宜。

一个小例子（退化变换下才成立，可手算）：$M = \operatorname{diag}(1,2,0)$，把 z 方向压扁。 $\det M = 0$，逆不存在；但 $\operatorname{adj}(M)^{\mathsf T} = \operatorname{diag}(0,0,2)$， 作用在 $\mathbf{n} = (0,0,1)$ 上得到 $(0,0,2)$，归一化后是 $(0,0,1)$。

物体被压成 $z = 0$ 平面，而这个平面的法线正是 $(0,0,1)$——伴随给出了正确答案。

在 shader 里怎么写#

绝大多数情况下你不需要在 shader 里算它——法线矩阵每个物体算一次，CPU 端算好传 uniform 是标准做法。 真要在 GPU 上算（GPU skinning 里每根骨骼一个矩阵、程序化变形），用这个恒等式：

$$\operatorname{adj}(M)^{\mathsf T} = \text{余子式矩阵 } C$$

也就是不必"先求伴随再转置”，直接构造 $C$ 就行；而 3×3 的 $C$ 的三列正好是原矩阵两两列的叉积：

// GLSL 的 mat3(a,b,c) 是「列为 a,b,c」；m[0] 是第一列
mat3 cofactorMatrix(mat3 m) {
    return mat3(cross(m[1],m[2]), cross(m[2],m[0]), cross(m[0],m[1]));
}

mat3 M = mat3(model);
vec3 n_world = cofactorMatrix(M) * n_object;
// ⚠ 镜像（det < 0）时必须补一个符号，否则法线是反的！
n_world = normalize(sign(determinant(M)) * n_world);

这个符号不是多此一举：前面已经推出 $C = \operatorname{adj}(M)^{\mathsf T} = \det(M)\,M^{-\mathsf T}$，而 $\det(M)$ 带符号。

2000 组随机矩阵实测：
  det > 0（保向）：与 M⁻ᵀ 方向相同 1005 组，相反 0 组
  det < 0（镜像）：与 M⁻ᵀ 方向相同 0 组，相反 995 组   ← 全反

漏掉这个符号，只有镜像物体上的法线是反的——别的物体全对，最难查的那种 bug。

但修符号要算 $\det M$，而 $M^{-\mathsf T}$ 本来就要算它（求逆的除法用得到）。 所以伴随版省下的只是一次除法。这够不够抵消多出来的一次符号修正？把两种写法各编一遍看字节码：

transpose(inverse(m))      SPIR-V 18 条指令 —— 其中"求逆"是一条**语义指令**，
                           驱动还得把它展开成余子式 + det + 除法
cofactor(m) + sign(det)    SPIR-V 22 条指令 —— 3 个 Cross + Determinant + FSign，已经展开完了

伴随版在执行层面确实略快：它省掉的那次除法（GPU 上要多周期）比加上的 sign 值钱， 而且没有任何除法意味着极端缩放下的精度也更好。所以这个方案本身是成立的， 本节开头那句"伴随不需要除法"也不是空话。

但差距只有几条指令，而代价是一个"漏了就在镜像物体上出错"的坑。 这笔账怎么算都不划算——真要省，就别在 shader 里算（见下文决策表与结论第 ③ 条）。

另外两个注意点：顺序必须是循环移位的三对叉积；叉积含大数相减，极端缩放下会掉精度。

四、什么时候你根本不用这么麻烦#

RTR4 4.1.7 给了一个常被忽略的省略条件：变换只由平移 + 旋转 + 均匀缩放组成时（不含拉伸、挤压、切变），

  • 平移不影响法线（法线是向量）
  • 均匀缩放只改变长度，不改变方向
  • 旋转矩阵的转置就是它的逆 → 两次转置（或两次求逆）相互抵消

所以原矩阵 $M$ 可以直接用来变换法线。

归一化同样能省：

  • 只有平移 + 旋转：长度不变，根本不需要归一化
  • 再加均匀缩放 $s$：长度变成 $s$ 倍，除以 $s$ 即可

决策表#

变换组成 法线变换 归一化
平移 不需要变换 —
平移 + 旋转 直接用 $M$ 不需要
平移 + 旋转 + 均匀缩放 直接用 $M$ 除以缩放因子
含非均匀缩放 / 切变 必须 $M^{-\mathsf T}$（或 $\operatorname{adj}^{\mathsf T}$） 必须
投影等奇异变换 必须 $\operatorname{adj}^{\mathsf T}$ 必须
切向量 T / B 永远直接用 $M$ 视情况

只想拿结论的话，这张表就够了。

五、几个相关的坑#

TBN 里三个向量为什么不一样：切向量跟着几何走（按 $M$），法线要保持垂直性（按 $M^{-\mathsf T}$）。 在"均匀缩放 + 旋转"下两者恰好一致，所以写错了也不暴露；一旦有非均匀缩放，法线贴图立刻不对。 工程上更省事的做法是只存切线 $\mathbf{T}$，副切线用 $\mathbf{B} = \mathbf{N}' \times \mathbf{T}'$ 现场叉乘—— 省一个顶点属性，也躲开”$\mathbf{B}$ 该按哪个矩阵变换"的纠结。

负缩放（镜像）最容易混：它翻转的不是法线，是手性——用 $M^{-\mathsf T}$ 算出的法线自动正确 （$\det M$ 的符号已含在里面）。真正要处理的是依赖左右手系的量：三角形绕序与剔除方向 （UE 判 IsLocalToWorldDeterminantNegative()）、TBN 副切线方向 （Godot 存 binormal_sign、UE 存 TangentToWorldSign）。 而"双面材质翻法线"（UE 的 TwoSidedSign）是另一回事——那是面朝向。

归一化时机：顶点着色器里归一化远比逐像素便宜，但插值会改长度，走法线贴图的路径仍需再归一化一次。 跨平台：移动端 mediump 动态范围不够，法线矩阵相关计算用 highp；逐像素归一化要开方，低端设备上不免费。

“负缩放要翻转法线"这句话为什么容易把人绕进去：它混了三件不同的事，只是起因相同（$\det M < 0$）：

① 建模层：镜像一个模型 → 三角形绕序反 → 面的正反面颠倒
   → 建模工具里要"Flip Normals"（Blender）——说的是**绕序**
② 着色器层：用伴随当法线矩阵 → 补 $\operatorname{sign}(\det M)$
   —— 说的是**法线向量**，但用 $M^{-\mathsf T}$ 就没这问题
③ 手性层：TBN 副切线方向、剔除方向——说的是**手性**

所以这句话单看判不了对错——先问清说的是哪一个。三者处理位置不同，混着说必然自相矛盾。

小结#

  • 法线的身份由"与切向量的关系"定义，所以它按 $M^{-\mathsf T}$ 而不是 $M$ 变换
  • 这个解唯一到一个标量因子——于是伴随矩阵能顶替逆矩阵，而归一化不能省
  • 但在"平移 + 旋转 + 均匀缩放"下原矩阵就是对的（均匀缩放会改长度，除一下缩放因子即可）

下次写下 transpose(inverse(...)) 之前先问一句：这个物体的变换里有非均匀缩放吗？ 没有就可以省掉；有，就知道为什么省不掉。

  → 为什么既要求逆又要转置（切线是"跟着坐标系走"的量，法线是"反着走"的量）

  → 矩阵奇异、逆不存在怎么办（伴随矩阵）
  → 切向量为什么不一样（同一个变换，两类量的变换规则相反：逆变 / 协变）
  → 负缩放下法线贴图为什么会错
